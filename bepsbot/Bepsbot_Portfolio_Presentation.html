01

The Engineering Brief

Problem → constraints → solution

Engineering brief: build a system that measurably improves supportive communication in mental-health communities, without trusting the LLM to be safe or factual on its own. That brief produced three hard engineering requirements.

R1 · Measurable

Support quality must be scored, not guessed — a regression model over psycholinguistic features, benchmarked against expert labels (10-fold CV, F1, R²).

R2 · Grounded

Generation must be retrieval-augmented — the LLM writes with real, high-quality examples in context, never from hallucination.

R3 · Safe

Every input and every generated candidate passes an LLM safety moderator — dangerous advice, self-harm encouragement, and toxicity are blocked or masked.

Constraint-driven design Scoring is done by local transformers (fast, private, free at inference); the LLM is reserved for generation + moderation where its fluency matters. Every component degrades gracefully — the UI never crashes.

Core Pipeline

The dual-mode algorithm

The engine room: safety-gated, constrained, parallel generation. This is the exact control flow from the codebase.

# backend_api.py → /recommend_candidates def recommend_candidates(req): is_safe, reason = safety_filter.is_safe(req.comment) # LLM gate · temp=0 if not is_safe: return {"is_safe": False, "reason": reason} candidates = gen_recommender.generate_candidates(req.op_text, req.comment) # 3 × LLM, parallel # per-candidate moderation, parallel with ThreadPoolExecutor(max_workers=3) as ex: for future in as_completed({ex.submit(check, k, v): k for k, v in candidates.items()}): key, safe, why = future.result() if not safe: candidates[key] = f"[Content Filtered: {why}]" return {"is_safe": True, "candidates": candidates}
Mode A · Assessment
  1. RoBERTa IS + ES regression → float scores.
  2. LIWC-2015 vector + TextBlob → explainable features.
  3. Threshold tiers select the feedback opener.
  4. Weakest of ppron / social / posemo gets the targeted suggestion, with 12 sampled LIWC words.
Mode B · Recommendation
  1. LLM safety gate on the user's input.
  2. 3 constrained rewrites in parallel, each RAG-grounded.
  3. Parallel safety check on all 3 outputs; unsafe ones masked.
  4. Dedupe + rule-based fallback guarantees 3 distinct candidates.

RAG Engineering

Retrieval-augmented generation

Two generations of retrieval: the current codebase ships a ChromaDB RAG pipeline; the HHME 2026 paper documents the earlier two-stage Elasticsearch + BERT pipeline. Same principle — prove it with examples before you generate.

Index build (offline)
# build_vector_db.py good = df[(df.IS_rating >= 3) | (df.ES_rating >= 3)] # quality gate docs = [Document(page_content=r.comment_body, metadata={"IS": r.IS_rating, "ES": r.ES_rating}) for _, r in good.iterrows() if len(r.comment_body.split()) >= 5] Chroma.from_documents(docs, embedding=HuggingFaceEmbeddings( model_name="all-MiniLM-L6-v2"), persist_directory="chroma_db")
Query-time retrieval
# models/generative_recommender.py def _get_rag_context(self, query_text, k=3): results = self.vector_db.similarity_search(query_text, k=k) examples = "\n\n".join(f"Example {i+1}: {d.page_content}" for i, d in enumerate(results)) return f"\nHere are some high-quality examples:\n{examples}\n" # query = OP text → situation-matched examples → prompt
Paper pipeline — 2-stage retrieval
Elasticsearch More-Like-This (tf-idf, 50 candidates) → 768-d BERT cosine re-ranking → top examples
▼
Code pipeline — ChromaDB RAG
all-MiniLM-L6-v2 384-d → similarity_search(k=3) on quality-gated docs
▼
Prompt injection
examples positioned as few-shot inspiration — "use for tone and structure, but do not copy directly"
Same-embedding invariant The embedder used at build time must exactly match the one at query time — the code enforces this by reusing the identical model string. Chroma failure degrades gracefully: retrieval returns "" and generation continues ungrounded.

LLM Engineering

DeepSeek · prompts · safety · concurrency

One model (deepseek-chat via OpenAI SDK), two engineered jobs with deliberately different temperatures — creative generation at 0.7, deterministic moderation at 0.0.

Constrained generation
# one constraint per candidate → 3 distinct outputs constraints = [ ("candidate_1", "Personal Pronouns", 'Use "I", "we", "my", "our" to show connection'), ("candidate_2", "Family/Friends", 'Mention "friend", "family", "partner"'), ("candidate_3", "Positive Words", 'Use "hope", "strength", "better"'), ] # ThreadPoolExecutor(max_workers=3) → ~1× LLM latency, not 3×
Safety moderation
# models/safety_filter.py · temp=0.0 · max_tokens=50 """You are a safety moderator for a mental health peer support platform. Detect: dangerous advice · self-harm encouragement · toxic/hateful language · irrelevance. Return "UNSAFE: <reason>" or "SAFE".""" verdict = llm(...) # starts with SAFE → allowed
  • Two moderation passes per recommendation: input gate before generation + parallel per-candidate gate after (up to 4 moderation calls + 3 generations, two thread-pool waves).
  • "Return ONLY the text" keeps LLM output clean for the UI.
  • Fail-open policy on API errors — moderation never blocks valid traffic during an outage.

Decision & Feedback Engineering

Deterministic logic around the models

The part that makes the system feel intelligent: a deterministic, explainable decision layer around the neural predictions. Six decision points, zero black boxes.

Score → feedback tier
# app.py /assess if IS < 3 and ES < 3: # both low → gentle guidance f1 = "Here are my small suggestions:" elif IS == 3 and ES == 3: # both perfect → praise f1 = "Excellent! You can polish the comment if you want:" else: # mixed → one targeted tip f1 = "Great! There is one point I think you could improve:" # then attack min(ppron, social, posemo) with 12 sampled LIWC words
Feature vector
# util.py get_vector() dic = extract(lex, doc) # LIWC-2015 proportions vec = np.array([dic.get(c, 0) for c in cats]) vec = np.append(vec, len(sent_tokenize(doc))) # #sentences vec = np.append(vec, len(TweetTokenizer().tokenize(doc))) # #words blob = TextBlob(doc) vec = np.append(vec, [blob.sentiment.polarity, blob.sentiment.subjectivity])

Why deterministic? The feedback layer is explainable, unit-testable, and free to run — the LLM never touches the assessment path. Random sampling (word banks + templates) keeps messages from feeling robotic.

Model benchmarks + human study

Behavioral archetypes (the interesting finding)

A · Validation

66.7% used AS as a confirmation checkpoint and submitted unchanged — feedback as validation, not revision.

B · Selective Integration

20.5% blended suggestions into their own voice.

C · Full Replacement

12.8% adopted the generated draft wholesale — autonomy concern.

Design implication AI writing support should augment reflection, not automate authorship — evaluative transparency and voice preservation matter more than full automation. This directly shaped the next iteration direction (context-adaptive generation).

Reliability & Security Engineering

Graceful degradation by design
FailureFallback behavior
FastAPI backend downAssessment → scores 0 · Recommendation → original + rule-based polish
Model files missing/predict_scores returns zeros · UI unaffected
LLM API errorGeneration returns user draft · safety fails open (never blocks valid traffic)
Chroma load failureRAG context "" · generation continues ungrounded
Empty / duplicate candidatesRule-based polish + "(emphasis)" suffix → 3 distinct guaranteed
Elasticsearch downIndexing scripts fail only · main UI flow unaffected
Security controls
  • All credentials via environment variables; .env gitignored.
  • LLM moderation on both input and output (self-harm, harmful medical advice, toxicity).
  • Elasticsearch over HTTPS + basic auth + CA verification.
  • Sensitive data (record/, chroma_db/, models) excluded from git.
MLOps loop

record/ → clean & safety-filter → pseudo-label with current models → append CSV → retrain RoBERTa → validate (MSE / R² / safety pass rate) → promote to serving path → monitor drift (score shift, fallback rate, block rate, acceptance).
